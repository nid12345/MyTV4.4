# MyTV4.4

在 **Android 4.4（API 19）** 老机顶盒 / 老电视盒子上可用的 IPTV 直播播放器。

面向的是「系统停在 4.4、装不了新版 App、但硬件还能用」的那批设备：整个界面与控制逻辑
不依赖 Jetpack Compose、不依赖 Media3，用系统原生 View + 老版本依赖重写，**能在
Android 4.4.2 上流畅跑**。

## 功能

- **直播播放**：M3U / TXT（`#genre#` 格式）直播源，HLS 与普通流；多线路自动降级重试
- **订阅源管理**：内置默认源 + 自定义源；源分组显隐记忆（换源 / 重启后保持）；可设本地缓存时长。
  内置源含 **潮剧**（`nide.qzz.io/chaoju/chaoju.txt`，126 个剧目、26 个分类，多为整部戏拆条的多线路形式）
- **节目单（EPG）**：XMLTV 源；**内置多个节目单，主源失效时自动依次回退**；内置节目单管理列表（切换 / 删除 / 新增自定义源）
- **经典三段式选台面板**：分组栏 / 频道列 / 节目单列，三态平移；分组栏焦点自动定位；
  **不会定时自动收起** —— 只在选中频道 / 按返回键 / 点面板外空白时才隐藏
- **面板支持触屏手势**：面板展开后，**左滑深入一层、右滑退回一层**（分组 → 频道 → 节目单 → 收起），
  退到最后一级自动收起面板；遥控器方向键的语义与之完全一致
- **频道项两行显示**：频道名 + 当前节目名 + 行底进度条
- **节目信息栏**：台标 + 频道名 + 线路 / 清晰度 / 立体声 / 网速 + 当前与下一节目（含进度条）
- **收藏**：长按收藏，**跨订阅源保留**（收藏时一并记录线路快照）
- **设置页改完某项后停在原处**：设置列表里改完任意一项，光标仍留在那一项上，
  不会跳回列表开头（触摸点开关、遥控器按确认键两条路径都覆盖）
- **记忆上次频道**：退出重开直接回到上次观看的频道
- **DLNA 投屏**：SSDP 发现局域网 MediaRenderer，AVTransport 推送当前频道；
  **点一次设备即开始投送**，投送成功后才收起面板并提示结果，失败会留在面板上给出原因
- **播放控制弹层**：可拖动的进度条 + 播放/暂停 + 快退/快进 30 秒 + 多线路入口
- **多线路选框**：屏幕**右侧**弹出同频道的全部线路（含地址详情、当前在用标记），选中即切
- **多线路顺序连播**：同一节目内的多条线路是一条条**顺序**播下去的 —— 线路 1 播完自动接线路 2，
  直到第 N 条播完，才顺延到下一个节目；下一个节目同样从线路 1 开始。
  对「整部戏拆成多条线路」的潮剧 / 戏曲类源，可以一口气连着看完不用手动切
- **点播源自动连播**：一部播完自动接下一个视频，同分组播完自动接下一个分组
- **节目回看**：节目单里点已结束的节目，若本频道带实时回看线路（`tvod` / `playseek`）就直接回看；
  不带就明确提示「已结束 · 本频道不支持回看」，不会出现开发阶段的占位文案
- **换源卡死自愈**：多次换源后画面卡住时自动换线路；仍不出画面则自动重连，不用退应用
- **切到别的应用自动暂停**：跳到其他应用（含系统安装器、锁屏）时画面自动暂停；
  回到播放界面自动恢复播放，直播会直接跳回直播沿（不会停在暂停前的旧画面上）。
  自己手动按过的暂停不会被误恢复
- **遥控器友好**：支持数字选台、返回键连按两次退出、长按收藏
- **触屏手势**（面板/弹层不在屏时）：上滑下一频道、下滑上一频道；
  左右滑**循环**切换线路（左滑 = 下一条，右滑 = 上一条）
- **实时网速**：底栏与频道信息块的网速为播放链路的真实下载速率（每 0.5 秒刷新）
- **首次启动《使用须知》**：免责声明全屏页，同意一次后不再出现
- **应用内升级**：设置 → 应用 → 检查更新，弹出可见的下载进度层并可取消，下完后再由用户点「安装」；
  清单与安装包均**先并发探测再下载**，国内网络会自动挑当前可用的加速镜像
- **无广告、无统计、不申请存储 / 通讯录 / 位置等任何敏感权限**

## 安装

侧载安装（无应用商店）：

```bash
adb install -r MyTV4.4-v1.12-legacy17.apk
```

或把 APK 拷进 U 盘 / 存储卡，用盒子自带的文件管理器安装（需允许「未知来源」）。

- 应用名：**MyTV4.4**，包名：`top.yogiczy.mytv.legacy`
- 首次启动直接进播放页，无引导页 / 协议页
- 默认直播源可在「设置 → 直播源 → 自定义直播源」里改

## 构建

环境：JDK 17、Android SDK（compileSdk 34 / minSdk 19）

```bash
# 1) 准备签名配置（可选：不配也能编译，只是 release 产物未签名）
cp keystore.properties.example keystore.properties
#    然后填入你自己的 keystore 路径与密码

# 2) 构建
./gradlew assembleDebug     # 调试包
./gradlew assembleRelease   # 正式包（签名取决于 keystore.properties 是否存在）
```

> ⚠️ `keystore.properties` 与 `keystore/` 均在 `.gitignore` 中，**签名材料不会进仓库**。

## 应用内升级通道

分发走 GitHub，不需要任何自建服务器：

1. **版本清单**：仓库里的 [`update/version.json`](update/version.json)

   ```json
   {
     "versionCode": 17,
     "versionName": "1.12-legacy.17",
     "url": "https://github.com/nid12345/MyTV4.4/releases/download/v1.12/MyTV4.4-v1.12-legacy17.apk",
     "size": 10334270,
     "md5": "a202ef278701af18bfd513b990a2afdb",
     "notes": "更新说明，可多行"
   }
   ```

2. 客户端「设置 → 应用 → 检查更新」拉清单 → 比 `versionCode` → 提示 → 下载（带进度层）→ 拉起系统安装器。

清单与安装包都有**多线路自动回退**，不需要用户手动选线路。v1.11 起改为**先并发探测、再决定用哪条**：

| 线路 | 清单 | 安装包 |
|---|---|---|
| ghproxy 系加速镜像 ×5（`gh.llkk.cc` / `gh-proxy.com` / `ghfast.top` / `edgeone.gh-proxy.com` / `ghproxy.net`） | ✅ | ✅ |
| jsDelivr 镜像 | ✅ | —（jsDelivr 不代理 Release 附件） |
| GitHub 直连（`raw.githubusercontent.com` / Releases） | ✅ | ✅ |

探测只取前 1KB（`Range: bytes=0-1023`），5 条并发、先响应者胜，总等待上限 12 秒。
**国内直连 GitHub 常年不通，老代码把直连排第一、超时 20s/120s，用户点完「立即更新」要干等两分钟**
—— 现在这段等待被压到 1~2 秒，并且自动落到能用的镜像上。所有线路都探测失败时**不会直接判失败**，
仍会按原顺序逐个真下（下载超时更长，能接住"探测被误杀但实际可下"的情况）。

**v1.12 起下载目录也不再写死**。以前固定往
`/storage/emulated/0/Android/data/<包名>/files/update` 写，小米电视等机型该目录受系统限制会直接报
`无法创建下载目录`，升级链路整条断掉。现在按顺序试 5 个候选目录，并对每个目录做**真实写探针**
（只判断 `mkdirs()` 返回值不够 —— 目录建得出来但写进去仍可能 `EACCES`）：

| 顺序 | 候选目录 | 说明 |
|---|---|---|
| 1 | `getExternalFilesDir(null)/update` | 应用专属外部目录，优先 |
| 2 | `Environment.getExternalStorageDirectory()/Android/data/<包名>/files/update` | 部分定制 ROM 只认这条路径 |
| 3 | `filesDir/update` | 转内部存储，几乎所有设备都能写 |
| 4 | `externalCacheDir/update` | 外部缓存兜底 |
| 5 | `cacheDir/update` | 内部缓存最终兜底 |

失败提示也做了区分：目录类失败提示「本机存储不可写，请清理空间或检查电视的存储权限后重试」，
其余才提示网络方向。API < 24 走内部目录安装时，会先把安装包的父目录与文件本身放开读权限
（`setReadable(true, false)`），否则 `/data/data` 下的包交给系统安装器会读不到。

## 权限说明

本应用**只申请下面 6 项权限，全部与播放直接相关，没有读取存储、通讯录、位置、电话等任何敏感权限**：

| 权限 | 用途 | 不授予会怎样 |
|---|---|---|
| `INTERNET` | 拉取直播源列表、节目单、台标，播放网络流，检查更新 | 完全无法使用 |
| `ACCESS_NETWORK_STATE` | 判断网络是否可用、是否在计费网络 | 网络异常时提示不准 |
| `ACCESS_WIFI_STATE` | 读取 WiFi 状态（多播锁需要） | 投屏可能失败 |
| `CHANGE_WIFI_MULTICAST_STATE` | **DLNA 投屏**：SSDP 靠组播发现局域网内的电视 / 盒子；没有它息屏后会大量丢包 | 搜不到投屏设备 |
| `WAKE_LOCK` | 播放期间保持唤醒，避免看着看着息屏 | 可能中途黑屏 |
| `REQUEST_INSTALL_PACKAGES` | **应用内升级**：下载完成后拉起系统安装器（仅 API 26+ 需要，安装仍由系统弹窗确认） | 升级时无法自动拉起安装器 |

> 应用**不申请** `WRITE_EXTERNAL_STORAGE`：升级包下载到应用专属目录
> （首选 `getExternalFilesDir("update")`，不可写时按上表依次回退），再用 `FileProvider`
> （API < 24 走 `file://` + 放开读权限）交给安装器。

## 已知限制

- 仅支持 **Android 4.4 及以上**；Android 4.3 及更早未测试。
- **应用图标 / 界面为深色主题**，未适配浅色系统。
- 「自定义节目单」：内置节目单与自定义节目单统一在「设置 → 节目单 → 自定义节目单」的
  **管理抽屉**里切换 / 删除 / 新增；当前源失效时按内置顺序自动回退到下一个。
- **不支持「混合模式」**：上游 1.7 的混合模式依赖内置 WebView 播放器播放 `hybrid-webview://`
  地址，本工程没有实现该播放链路，因此设置项一并移除（避免给出不可播的线路）。
- DLNA 投屏依赖局域网组播，部分路由器开启「AP 隔离」时会搜索不到设备。
- 部分老设备（Android 4.4）的硬件解码器不支持高码率 1080p High Profile 直播流，
  表现为黑屏但有声音 —— 这是解码器能力问题，可切换到较低画质的线路。
