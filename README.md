# MyTV4.4

在 **Android 4.4（API 19）** 老机顶盒 / 老电视盒子上可用的 IPTV 直播播放器。

面向的是「系统停在 4.4、装不了新版 App、但硬件还能用」的那批设备：整个界面与控制逻辑
不依赖 Jetpack Compose、不依赖 Media3，用系统原生 View + 老版本依赖重写，**能在
Android 4.4.2 上流畅跑**。

## 功能

- **直播播放**：M3U / TXT（`#genre#` 格式）直播源，HLS 与普通流；多线路自动降级重试
- **订阅源管理**：内置默认源 + 自定义源；源分组显隐记忆（换源 / 重启后保持）；可设本地缓存时长。
  内置源含 **潮剧**（`nide.qzz.io/chaoju/chaoju.txt`，126 个剧目、26 个分类，多为整部戏拆条的多线路形式）
- **节目单（EPG）**：XMLTV 源；**内置多个节目单，主源失效时自动依次回退**；内置节目单管理列表（切换 / 删除 / 新增自定义源）
- **经典三段式选台面板**：分组栏 / 频道列 / 节目单列，三态平移；分组栏焦点自动定位；
  **无操作 15 秒才自动收起**（比其它弹层的 5 秒长），选中频道 / 按返回键 / 点面板外空白则立即收起
- **二级菜单上下键跨分组顺延**：所有直播源分组（我的收藏 + 各频道分组）行为**完全一致** ——
  末项按下 → 下一分组首项；首项按上 → 上一分组末项；**空分组自动跳过**；
  第一个分组首项按上、最后一个分组末项按下**都不跳**；
  「换源」和「系统应用」**不参与跨组**（焦点不会落上去）；切换任意订阅源后立即生效
- **面板内按住方向键快速挑选**：面板展开时**长按「下键」不再弹出播放控制菜单**，
  按住不放就是一路往下挑节目（与长按「上键」对称）；播放控制入口保留在面板收起时
- **一二级菜单是一个整体**：分组栏 / 频道列 / 节目单列拼接处一律直角，
  只有整块面板最外圈的四个角做圆角，展开节目单后同样是"一整块"
- **面板底部与右下角信息框底边对齐**；一级菜单底 90% 不透明、二级菜单与信息框 70%；
  信息框高度不超过整屏 1/5，内容多时只有频道名保持大号、其余文字缩小并以省略号收尾
- **展开面板时先收起左下角临时信息块**，两者不会同时挂在屏幕上
- **除设置页外，所有在直播界面唤起的菜单/窗口都会自动隐藏**：任何按键或触摸即重新计时；
  弹层超时取「设置 → 界面 → 超时自动关闭界面」（默认 5 秒），设置页永不自动关闭
- **换源列表只显示源名**：不留台标（头像）位、不显示网址，名字直接顶到左边；在用源行尾标「使用中」
- **面板支持触屏手势**：面板展开后，**左滑深入一层、右滑退回一层**（分组 → 频道 → 节目单 → 收起），
  退到最后一级自动收起面板；遥控器方向键的语义与之完全一致
- **频道项两行显示**：频道名 + 当前节目名 + 行底进度条
- **节目信息栏**：台标 + 频道名 + 线路 / 清晰度 / 立体声 / 网速 + 当前与下一节目（含进度条）
- **收藏**：长按收藏，**跨订阅源保留**（收藏时一并记录线路快照）
- **设置页改完某项后停在原处**：设置列表里改完任意一项，光标仍留在那一项上，
  不会跳回列表开头（触摸点开关、遥控器按确认键两条路径都覆盖）
- **记忆上次频道**：退出重开直接回到上次观看的频道
- **崩溃记录 + 一键反馈**：崩了以后重启**照常可用**（不再卡在一个按不动的页面）；崩溃堆栈会存下来，
  弹窗里点「一键反馈」就直接上传（v1.18 起走**腾讯 Bugly**，免 Token、电视端零配置）；
  也可以「复制记录」或从「设置 → 关于 → 崩溃记录」随时查看
- **DLNA 投屏**：SSDP 发现局域网 MediaRenderer，AVTransport 推送当前频道；
  **点一次设备即开始投送**，投送成功后才收起面板并提示结果，失败会留在面板上给出原因
- **播放控制弹层**：可拖动的进度条 + 播放/暂停 + 快退/快进 30 秒 + 多线路入口
- **多线路选框**：屏幕**右侧**弹出同频道的全部线路（含地址详情、当前在用标记），选中即切
- **多线路顺序连播**：同一节目内的多条线路是一条条**顺序**播下去的 —— 线路 1 播完自动接线路 2，
  直到第 N 条播完，才顺延到下一个节目；下一个节目同样从线路 1 开始。
  对「整部戏拆成多条线路」的潮剧 / 戏曲类源，可以一口气连着看完不用手动切
- **点播源自动连播**：一部播完自动接下一个视频，同分组播完自动接下一个分组
- **节目回看**：节目单里点已结束的节目，若本频道带实时回看线路（`tvod` / `playseek`）就直接回看；
  不带就明确提示「已结束 · 本频道不支持回看」，不会出现开发阶段的占位文案
- **换源卡死自愈**：多次换源后画面卡住时自动换线路；仍不出画面则自动重连，不用退应用
- **切到别的应用自动暂停**：跳到其他应用（含系统安装器、锁屏）时画面自动暂停；
  回到播放界面自动恢复播放，直播会直接跳回直播沿（不会停在暂停前的旧画面上）。
  自己手动按过的暂停不会被误恢复
- **遥控器友好**：支持数字选台、返回键连按两次退出、长按收藏
- **触屏手势**（面板/弹层不在屏时）：上滑下一频道、下滑上一频道；
  左右滑**循环**切换线路（左滑 = 下一条，右滑 = 上一条）；
  **屏幕最左 / 最右各 1/6 宽**的区域内上下滑 = 调亮度 / 调音量（只在完全没有弹层时生效，
  调节条本身不拦触摸，滑的时候照样能继续调）
- **实时网速**：底栏与频道信息块的网速为播放链路的真实下载速率（每 0.5 秒刷新）
- **首次启动《使用须知》**：免责声明全屏页，同意一次后不再出现
- **应用内升级**：设置 → 应用 → 检查更新，弹出可见的下载进度层并可取消，下完后再由用户点「安装」；
  清单与安装包均**先并发探测再下载**，国内网络会自动挑当前可用的加速镜像
- **无广告、无统计、不申请存储 / 通讯录 / 位置等任何敏感权限**

## 菜单与触屏操作规则

### 一、直播源二级菜单的上下键（跨分组）

所有**直播源分组**（我的收藏、以及央视频 / 卫视频 / 地方频道等所有分组）的二级菜单，
上下键跨组逻辑**完全一致**：

| 场景 | 行为 |
|---|---|
| 二级菜单**最后一项**按 `↓` | 跳到**下一个分组**二级菜单的**第一项** |
| 二级菜单**第一项**按 `↑` | 跳到**上一个分组**二级菜单的**最后一项** |
| 第一个分组的第一项按 `↑` | **不跳**（没有上一个了） |
| 最后一个分组的最后一项按 `↓` | **不跳**（没有下一个了） |
| 中间某个分组是空的 | **自动跳过**，落到下一个有内容的分组 |
| 「换源」「系统应用」 | **不参与跨组**，焦点也不会顺延落到这两项上 |

切换任意一级订阅源后，上述逻辑**立即生效**（规则按分组名判定，不写死序号，
所以不同订阅源的分组数量不一样也不会失效）。

### 二、设置页的一级 / 二级菜单

1. 一级菜单（左栏）选中某一项 → 右栏立刻显示对应的二级菜单；
2. 一级菜单上按 **`→` 或 `OK`** → 焦点进入二级菜单（落在第一行）；
3. 二级菜单里按 `↑` / `↓` → **只在当前二级菜单内部移动，绝不跳到一级菜单**
   （到第一行再按上、到最后一行再按下，都停在原地）；
4. 只有按**返回键**或 **`←`**，焦点才回到一级菜单，且落在**当前这个二级菜单对应的那一项**上；
5. 切换一级菜单 → 二级菜单刷新，焦点规则同上。

### 三、触屏调节亮度 / 音量

- **最左侧 1/6 屏宽**的区域内上下滑 → 调亮度；**最右侧 1/6** → 调音量；
- **只有在播放界面完全没有弹窗 / 菜单时**才触发（左侧菜单、设置页、加载提示、
  任何弹层在屏时一律不触发）；
- 调节条是**不拦截触摸**的浮层：它显示的时候，在 1/6 区域继续上下滑**照样能调**，
  热区判定按全屏坐标算，不因浮层而改变。

## 崩溃记录与一键反馈

### 崩了之后会怎样

1. 崩溃瞬间把堆栈（机型 / Android 版本 / 应用版本 + 调用栈）写到本机；
2. 下次启动**界面照常构建、照常播放**，崩溃记录以弹窗形式盖在上面 ——
   遥控器左右选「一键反馈 / 复制记录 / 关闭」，**返回键也能直接关掉**；
3. 关掉之后这条记录就不再来挡你（下次启动只在底部提一行），
   想再看 / 再反馈就进「设置 → 关于 → 崩溃记录」；
4. 弹窗闲置 2 分钟会自动关，避免遥控器出问题时把人锁死在上面。

> v1.17 以前不是这样：那时崩了之后重启会**整个跳过界面构建**，屏幕上只剩一个
> 焦点够不到的按钮、返回键直接结束应用，退出重进还是同一屏 —— 只能卸载重装。
> 这个坑在小米电视（MI TV4-ANSM0 / Android 6.0.1）上报过一次，已修。

### 一键反馈到哪（v1.18 起：腾讯 Bugly，免 Token）

v1.18 把上报后端换成了**腾讯 Bugly**：国内直连、免费、有网页后台，
**电视端不需要任何配置**（v1.17 那套"在电视上填 GitHub Token"已整个删除 ——
国内连 `api.github.com` 本来就不稳，还要用户在遥控器和手机上倒腾一次 PAT，门槛太高）。

- **崩溃会自动上报**：Bugly SDK 在启动时初始化，此后 Java / Native / ANR 崩溃
  由 SDK 自己采集上报，不需要点任何按钮；
- **「一键反馈」按钮**：崩溃弹窗里的按钮还在，点一下就把本地存的那条记录
  **当作一次已捕获异常**交给 Bugly（堆栈按 `at ...` 行还原成真实的调用帧，
  后台看到的文件名与行号与真机一致）；
- 后台查看：bugly.qq.com →「MyTV4.4」→ 崩溃分析，同一条崩溃按
  「异常类型 + 版本」聚合，能直接看到复现次数。

#### 我需要做什么（开发者，一次即可）

SDK 需要一个 **App ID**，它是**编译期常量**，不写在电视上、也不让用户填：

1. <https://bugly.qq.com/v2/index> 用 QQ 登录；
2. 「产品管理 → 创建产品」→ 类型 **Android** → 包名填 `top.yogiczy.mytv.legacy`；
3. 把拿到的 **App ID** 填进 `app/src/main/java/.../data/CrashReporter.kt` 的
   `BUGLY_APP_ID`（同文件还有 `BUGLY_APP_KEY` 预留位）；
4. 重新编译安装即可。

**没填 App ID 时不会报错、不会起后台线程**，只会在点「一键反馈」时给出
"怎么配置"的说明，并提示先「复制记录」把堆栈直接发给开发者。

> 备选通道（用户给的第二个选项）：同一文件里的 `CRASH_UPLOAD_URL` 可以填
> **任意一个免鉴权的国内 HTTP 接口**，上报就走 `POST text/plain` 直传
> （带 `X-App-Version` / `X-Device-Model` 两个头）。Bugly App ID 优先，
> 只有它留空时才走这条。

兼容性：Bugly `crashreport 4.1.9.3` 的 `minSdkVersion` 是 **15**（读 AAR 内
AndroidManifest 实测），POM 无传递依赖，兼容本工程的 **API 19**；AAR 的 manifest
**不自带任何权限声明**，不会往合并后的清单里塞权限。

### 老设备的 TLS 根证书

Android 4.4 / 6.0 自带的 CA 库**不会再更新**，而 `api.github.com` 现在的证书链
（`Sectigo Public Server Authentication Root E46` ← `USERTrust ECC CA`）不在那份老库里，
会直接报 `Trust anchor for certification path not found`。v1.17 起随包附带 4 张公开根证书
（`app/src/main/assets/ca/`：USERTrust ECC / USERTrust RSA / ISRG Root X1 / DigiCert Global Root G2），
**先按系统信任链校验，不通过才用随包根证书再校验一次** —— 只"追加"可信根，不放松任何原有校验。

副作用是**好的**：老设备上「检查更新」原本也因为同一个原因一直在静默失败
（`raw.githubusercontent.com` / `ghproxy` 全是 Trust anchor 错误），这次一并修好了。

## 应用内升级通道

分发走 GitHub，不需要任何自建服务器：

1. **版本清单**：仓库里的 [`update/version.json`](update/version.json)

   ```json
   {
     "versionCode": 23,
     "versionName": "1.18-legacy.23",
     "url": "https://github.com/nid12345/MyTV4.4/releases/download/v1.18/MyTV4.4-v1.18-legacy23.apk",
     "size": 10944241,
     "md5": "e236b5cc24cb2a655ee6f8211c15cebb",
     "notes": "更新说明，可多行"
   }
   ```

2. 客户端「设置 → 应用 → 检查更新」拉清单 → 比 `versionCode` → 提示 → 下载（带进度层）→ 拉起系统安装器。

清单与安装包都有**多线路自动回退**，不需要用户手动选线路。v1.11 起改为**先并发探测、再决定用哪条**：

| 线路 | 清单 | 安装包 |
|---|---|---|
| ghproxy 系加速镜像 ×5（`gh.llkk.cc` / `gh-proxy.com` / `ghfast.top` / `edgeone.gh-proxy.com` / `ghproxy.net`） | ✅ | ✅ |
| jsDelivr 镜像 | ✅ | —（jsDelivr 不代理 Release 附件） |
| GitHub 直连（`raw.githubusercontent.com` / Releases） | ✅ | ✅ |

探测只取前 1KB（`Range: bytes=0-1023`），5 条并发、先响应者胜，总等待上限 12 秒。
**国内直连 GitHub 常年不通，老代码把直连排第一、超时 20s/120s，用户点完「立即更新」要干等两分钟**
—— 现在这段等待被压到 1~2 秒，并且自动落到能用的镜像上。所有线路都探测失败时**不会直接判失败**，
仍会按原顺序逐个真下（下载超时更长，能接住"探测被误杀但实际可下"的情况）。

**v1.12 起下载目录也不再写死**。以前固定往
`/storage/emulated/0/Android/data/<包名>/files/update` 写，小米电视等机型该目录受系统限制会直接报
`无法创建下载目录`，升级链路整条断掉。现在按顺序试 5 个候选目录，并对每个目录做**真实写探针**
（只判断 `mkdirs()` 返回值不够 —— 目录建得出来但写进去仍可能 `EACCES`）：

| 顺序 | 候选目录 | 说明 |
|---|---|---|
| 1 | `getExternalFilesDir(null)/update` | 应用专属外部目录，优先 |
| 2 | `Environment.getExternalStorageDirectory()/Android/data/<包名>/files/update` | 部分定制 ROM 只认这条路径 |
| 3 | `filesDir/update` | 转内部存储，几乎所有设备都能写 |
| 4 | `externalCacheDir/update` | 外部缓存兜底 |
| 5 | `cacheDir/update` | 内部缓存最终兜底 |

失败提示也做了区分：目录类失败提示「本机存储不可写，请清理空间或检查电视的存储权限后重试」，
其余才提示网络方向。API < 24 走内部目录安装时，会先把安装包的父目录与文件本身放开读权限
（`setReadable(true, false)`），否则 `/data/data` 下的包交给系统安装器会读不到。

## 权限说明

本应用**只申请下面 6 项权限，全部与播放直接相关，没有读取存储、通讯录、位置、电话等任何敏感权限**：

| 权限 | 用途 | 不授予会怎样 |
|---|---|---|
| `INTERNET` | 拉取直播源列表、节目单、台标，播放网络流，检查更新 | 完全无法使用 |
| `ACCESS_NETWORK_STATE` | 判断网络是否可用、是否在计费网络 | 网络异常时提示不准 |
| `ACCESS_WIFI_STATE` | 读取 WiFi 状态（多播锁需要） | 投屏可能失败 |
| `CHANGE_WIFI_MULTICAST_STATE` | **DLNA 投屏**：SSDP 靠组播发现局域网内的电视 / 盒子；没有它息屏后会大量丢包 | 搜不到投屏设备 |
| `WAKE_LOCK` | 播放期间保持唤醒，避免看着看着息屏 | 可能中途黑屏 |
| `REQUEST_INSTALL_PACKAGES` | **应用内升级**：下载完成后拉起系统安装器（仅 API 26+ 需要，安装仍由系统弹窗确认） | 升级时无法自动拉起安装器 |

> 应用**不申请** `WRITE_EXTERNAL_STORAGE`：升级包下载到应用专属目录
> （首选 `getExternalFilesDir("update")`，不可写时按上表依次回退），再用 `FileProvider`
> （API < 24 走 `file://` + 放开读权限）交给安装器。

## 已知限制

- 仅支持 **Android 4.4 及以上**；Android 4.3 及更早未测试。
- **应用图标 / 界面为深色主题**，未适配浅色系统。
- 「自定义节目单」：内置节目单与自定义节目单统一在「设置 → 节目单 → 自定义节目单」的
  **管理抽屉**里切换 / 删除 / 新增；当前源失效时按内置顺序自动回退到下一个。
- **不支持「混合模式」**：上游 1.7 的混合模式依赖内置 WebView 播放器播放 `hybrid-webview://`
  地址，本工程没有实现该播放链路，因此设置项一并移除（避免给出不可播的线路）。
- DLNA 投屏依赖局域网组播，部分路由器开启「AP 隔离」时会搜索不到设备。
- 部分老设备（Android 4.4）的硬件解码器不支持高码率 1080p High Profile 直播流，
  表现为黑屏但有声音 —— 这是解码器能力问题，可切换到较低画质的线路。
